# LeadGet Channel Bot — архитектура и пайплайн

Контент-система для Telegram-канала @Leadget_channel: новости рынка, кейсы клиентов LeadGet, посты про фичи продукта. Модерация через Google Sheets, публикация от лица пользователя через MTProto (полное HTML-форматирование: blockquote, анимированные эмодзи).

## Три слоя данных в одной Google-таблице

**News** — сырые новости. `collect.ts` (ежедневно 10:00 МСК) собирает кандидатов из Habr/Cossa/Reddit, LLM оценивает релевантность от 1 до 10. Порог прохождения подстраивается автоматически через `learn.ts`/лист `Preferences` (доверие по источнику: high/normal/low). Прошедшие порог новости получают статус `pending`, человек в таблице (или в веб-панели) ставит `approved`/`rejected`.

**ContentPlan** — план публикаций по дням: `Дата | Тип (новость/кейс/фича) | Заголовок | Токен | Данные (JSON) | Статус | Пост | Ссылка`. Человек добавляет строку на нужную дату со статусом `approved`. Для кейсов `caseScanner.ts` делает это автоматически при хорошей статистике кампании.

**AutoPosts** — журнал реальных публикаций, нужен для дедупликации (чтобы не запостить одну новость дважды).

**Cases** — кандидаты на кейс-посты: клиент, токен кампании LeadGet, ниша, отправлено/лиды/конверсия%, статус (pending/approved/add to plan/posted/skip).

**Features** — справочник идей фич: название, проблема, описание, статус (draft/approved/posted).

**Preferences** — то, чему научился бот: по каждому источнику новостей — сколько одобрено/отклонено, уровень доверия, и один общий порог релевантности.

## Публикация — autopost.ts

Часовой крон (10:00–20:00 МСК). Ищет в `ContentPlan` approved-строку на сегодня:

- **новость** — берёт самую высокорейтинговую `approved` строку из `News`, генерирует пост LLM (с учётом tone of voice), после публикации ставит `posted` и в `News`, и в `ContentPlan`. Публикуется ВСЕГДА без фото (решение принято сознательно — картинка не несёт данных, не стоит зависимости от Replicate).
- **кейс** — тянет статистику кампании из LeadGet API (`caseGen.ts`, обязательно нужна анонимизированная `niche` в поле `Данные` — без неё пост не создастся, чтобы не утёк реальное имя клиента), собирает пост с реальными цифрами, рисует доску-превью детерминированно (без ИИ-картинки), следом отдельным альбомом — 4 слайда переписки (тоже детерминированный рендер, текст диалога генерирует LLM по анонимизированным правилам).
- **фича** — пост про продуктовое улучшение, картинка через Replicate Flux с фиксированным маскотом.

Готовый пост форматируется (`formatter.ts`): `[QUOTE]` → blockquote, эмодзи → анимированные, числа/проценты/@упоминания дожимаются жирным даже если модель забыла их выделить, ссылки-источники защищены от попадания разметки внутрь URL.

## Tone of voice

`toneSamples.ts` перед каждой генерацией новостного поста тянет последние сообщения из Telegram через тот же MTProto-аккаунт: 5 постов из своего канала и несколько из обучающих каналов. Промпт держит 70% голоса из своих постов, адаптирует приёмы из обучающих — не копирует дословно.

## Обучение на решениях человека — learn.ts

По воскресеньям читает все решённые строки `News` (`approved`/`posted`/`rejected`), считает по каждому источнику одобряемость, находит порог релевантности, который лучше всего разделяет одобренные и отклонённые новости, и уровень доверия к источнику. Пишет в `Preferences`. `collect.ts` читает эти данные и подстраивает порог на лету: доверенным источникам — снижает планку (вплоть до авто-одобрения без участия человека), недоверенным — повышает.

## Веб-панель

Отдельное Next.js-приложение (`panel/`), задеплоено на Vercel: https://lead-get-channel.vercel.app. Разделы: Новости (очередь на approve/reject), Кейсы, Фичи (с формой добавления идей), План (контент-план карточками по неделям, с реальными данными кейса/фичи и ссылкой на опубликованный пост), Настройки (объясняет логику бота человеческим языком: порог, доверие к источникам, полные тексты промптов и формальных спек — что реально используется, а что нет).

## GitHub Actions workflows

- `main.yml` — `collect`+`scan-cases` ежедневно 10:00 МСК, `learn` по воскресеньям 11:00 МСК (отдельный workflow-файл специально, чтобы два cron-триггера в одном файле не конфликтовали).
- `autopost.yml` — `post` ежечасно 10:00–20:00 МСК (боевая публикация), плюс ручные `test-case`/`test-feature`/`test-news` для проверки форматирования без ожидания расписания.
- `articles.yml` — раз в 3 дня, опциональная генерация статей под внешние площадки.
