# Как подключить NotebookLM к этому проекту

У NotebookLM нет публичного API и нет прямой интеграции с GitHub — подключение всегда через ручную загрузку источников в notebooklm.google.com. Ниже — как сделать это с максимальной пользой и минимальными переделками в будущем.

## Что уже подготовлено

В этой папке 7 файлов — уже выжимка из кода в читаемый вид, специально под NotebookLM (вместо того чтобы скармливать ему сырой TypeScript, который модель хуже связывает в ответах):

1. `01-architecture-and-pipeline.md` — как вообще всё устроено: слои данных, пайплайн публикации, workflows
2. `02-content-prompts.md` — все текстовые промпты (новость/кейс/фича), структура постов, запреты
3. `03-image-prompts-and-mascot.md` — промпты для картинок, маскот, позы, запреты
4. `04-case-preview-spec.md` — формальная спека доски кейса (дословно)
5. `05-case-chat-spec.md` — формальная спека слайдов переписки (дословно)
6. `06-anonymization-rules.md` — правило анонимизации + разбор реального инцидента с утечкой
7. `07-sheets-and-panel-reference.md` — схема таблиц Google Sheets и разделов веб-панели

Семь источников — сознательный выбор: NotebookLM отвечает точнее, когда источников немного и каждый самодостаточен, а не десятки фрагментов кода вперемешку.

## Шаг 1 — создать Notebook

1. Открыть https://notebooklm.google.com
2. **+ Create new** → назвать, например, `LeadGet Channel Bot`
3. **Add sources** → **Upload** → выбрать все 7 файлов из `docs/notebooklm/` за один раз (можно выделить все сразу)

## Шаг 2 (рекомендую) — залить через Google Drive, а не просто Upload

Если загрузить файлы как обычные PDF/txt, при любом изменении промптов в коде источник в NotebookLM устареет и его придётся перезаливать руками. Более живой вариант:

1. Создать папку на Google Drive, например `LeadGet Bot / NotebookLM`
2. Конвертировать эти 7 `.md` в Google Docs (открыть в Google Docs, вставить содержимое — форматирование markdown-заголовков Google Docs поймёт как обычный текст, это не страшно)
3. В NotebookLM добавлять источники не через Upload, а через **Google Drive** — тогда у каждого источника появится кнопка **Sync** («О»/circular arrow), которая подтягивает новую версию файла с Drive одним кликом, без пересоздания источника

Тогда обновление workflow такое: поменял промпт в коде → обновил соответствующий Google Doc → нажал Sync на источнике в NotebookLM. Без API, но в один клик вместо пересборки ноутбука с нуля.

## Шаг 3 — настройки, которые реально полезны здесь

- **Notebook guide / Custom instructions** (шестерёнка ноутбука): задать что-то вроде «Отвечай на русском, если не спросили иначе. При вопросах про промпты цитируй точную формулировку из источника, не перефразируй.» — это снижает риск, что модель «додумает» правило, которого нет.
- **Audio Overview** («Обзор») — one-click подкаст-объяснение всей системы на 2 голоса. Полезно для онбординга нового человека в команде: не читать 7 доков, а послушать 10 минут.
- **Study guide / FAQ / Briefing doc** (кнопки в Studio-панели) — автогенерация шпаргалки или брифа, если нужно быстро ввести кого-то в курс дела.
- **Discover sources** — если возникнет вопрос за пределами текущих 7 доков (например «как вообще работает MTProto»), можно попросить NotebookLM самому найти релевантные внешние источники и предложить добавить — не обязательно искать вручную.

## Примеры вопросов, которые имеет смысл задавать

- «Какая структура у поста-новости, по порядку блоков?»
- «Что запрещено писать в любом посте?»
- «Что случилось с утечкой имени клиента и как это исправлено?»
- «Какие колонки в листе ContentPlan и что должно быть в поле Данные для кейса?»
- «Используется ли сейчас спека case-chat в реальных постах?» — источник 07 и 05 вместе дадут точный ответ (спека подключена к продакшену, см. `01-architecture-and-pipeline.md`, раздел «Публикация»).

## Поддержание в актуальном состоянии

Эти 7 файлов — снимок на момент создания (15.08.2026), не автосинхронизированный с кодом. Когда меняются промпты (`src/prompts.ts`, `src/brandDesign.ts`) или структура таблиц (`src/sheets.ts`) — обновляй соответствующий файл в `docs/notebooklm/` вручную (или попроси об этом следующей сессией) и синхронизируй в NotebookLM через Drive, как описано в шаге 2.
